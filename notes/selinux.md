## Briefly

By default SELinux will deny access to GPU, XWayland, and Wayland. Fixing those denials involves:
- creating SELinux policy
- applying SELinux policy to container deployment

On top of policies generated by `udica` required SELinux policy includes the next rules:
```
(allow process unconfined_t ( unix_stream_socket ( connectto )))
(allow process user_tmp_t ( unix_stream_socket ( connectto )))
```

If you are against it because of security reasons, your only options are:
- make SELinux inactive (worse than what was proposed)
- make container privileged (worse than what was proposed)
- dismiss using this guide and switch to the virtual machine
- dismiss using this guide and switch to the dedicated machine

### Create complete SELinux policy

Complete Clone repo, Build image and Deploy steps from [README Get started section](https://github.com/flexxxxer/podman-aosp/blob/master/README.md)

Next, dump container configuration to JSON:
```bash
podman inspect aosp-dev > ./aosp-dev.json
```

Next, generate an SELinux policy for the container via `udica` (requires root privileges on the host):
- for Intel GPUs:
  ```bash
  sudo udica -j ./aosp-dev.json --full-network-access \
    --devices /dev/kvm,/dev/dri \
    --X-access aosp_dev
  ```
- for AMD GPUs:
  ```bash
  sudo udica -j ./aosp-dev.json --full-network-access \
    --devices /dev/kvm,/dev/dri,/dev/kfd \
    --X-access aosp_dev
  ```

Next, append required SELinux policy rules, which aren't handled by `udica`:
```bash
awk '  { print }
  /blockinherit x_container/ && !done {
    print "    (allow process unconfined_t ( unix_stream_socket ( connectto )))"
    print "    (allow process user_tmp_t ( unix_stream_socket ( connectto )))"
    done = 1
  }
' aosp_dev.cil > aosp_dev.cil.new \
&& mv aosp_dev.cil.new aosp_dev.cil
```

Install a new SELinux policy into the host (requires root privileges on the host):
```bash
sudo semodule -i aosp_dev.cil /usr/share/udica/templates/{base_container.cil,net_container.cil,x_container.cil}
```

Verify if policy loaded (requires root privileges on the host):
```bash
sudo semodule -l | grep aosp_dev
```

### Apply SELinux policy to container deployment

It depends on your pod container deployment file, which depends the GPU vendor:
- For Intel GPUs:
  ```bash
  sed -i 's/^\([[:space:]]*\)securityContext:[[:space:]]*$/\1securityContext:\n\1  seLinuxOptions:\n\1    type: aosp_dev.process/' pods/full.intel-gpu.yaml
  ```
- For AMD GPUs:
  ```bash
  sed -i 's/^\([[:space:]]*\)securityContext:[[:space:]]*$/\1securityContext:\n\1  seLinuxOptions:\n\1    type: aosp_dev.process/' pods/full.amd-gpu.yaml
  ```

And redeploy via `podman kube play --replace --no-pod-prefix -` as per [README Deploy section](https://github.com/flexxxxer/podman-aosp/blob/master/README.md#deploy). After that ASfP should work fine as well as emulator.


### Remove SELinux policy

Requires root privileges on the host:
```bash
sudo semodule -r aosp_dev
```
